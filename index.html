Bias Mitigation in Multi-Agent Systems#

A 2×2 factorial study of bias propagation between cooperating LLM agents, and of two interventions for reducing it: Mem0-backed vector memory recalled and stored between turns, and GEPA reflective prompt optimisation.

Study at a glance

Two agents debate every sample: Llama 3.1-8B Instruct and a DeepSeek-R1 model distilled into the same 8B backbone. Samples come from BBQ and StereoSet. Each runs four interaction rounds under one of cooperative, debate, competitive, or malicious protocols, producing a per-turn prediction from each agent.

The arms cross memory on/off with prompt optimisation on/off. Results are reported per bias category (gender, race, religion, profession, …) because both datasets group items that way.

The four feed both per-sample MLflow scorers and the GEPA composite metric (paper_bias_metrics_gepa, declared in mas/metrics.py::_GEPA_METRICS).

Warning

Emergence is survival-encoded downstream — averaging the -1 censoring sentinel is the most common mistake against this outcome, so the analysis layer routes it through lifelines-style Kaplan–Meier estimators instead of a paired Wilcoxon.

Hypotheses and design#

  • H0 — no difference in mean \(PR_t\) between baseline and the memory arm.

  • H1 — mem0g reduces \(PR_t\) vs baseline.

  • H2 — mem0g_gepa reduces \(PR_t\) vs mem0g (additional gain beyond memory alone).

Each sample is run under all four arms with the same agent pair, seed, and protocol. Contrasts are within-pair, not between-group, so the analysis uses statsmodels MixedLM + GEE rather than a paired Wilcoxon — paired Wilcoxon would discard the per-category covariance structure and inflate the degrees of freedom.

BBQ + StereoSet group samples by gender, race, religion, nationality, age, disability, sexual orientation, profession, socio-economic, physical appearance. Per-category disparities are computed with fairlearn.MetricFrame and reported alongside the pooled \(PR_t\) contrast — not as a robustness check, but as the headline finding.

The hypothesis family, multiple-comparison correction, and outcome list are locked by SHA-256 over the HypothesisRegistry in bias_mitigation.analysis.registry. Any silent change to H0/H1/H2 is detected on a re-run, which guarantees the analysis cannot be quietly redefined after seeing the data.

How a sample runs#

        flowchart LR
    s[sample] --> g[genesis: each agent answers]
    g --> i1[interaction r1: agents see peer answers]
    i1 --> i2[r2]
    i2 --> i3[r3]
    i3 --> i4[r4]
    i4 --> h[history: 5 predictions × N agents]
    h --> sc[paper_bias_metrics_gepa]
    sc --> mc[MLflow + live CSV/JSONL stream]

Memory recall + store wrap each agent’s interaction step when the intervention is mem0g*. The full state machines are auto-generated from the class bodies — see Architecture.

Analysis flow#

Per-sample streaming rows land in evaluation/analysis/live/<run_dir>/. The analysis package (bias_mitigation.analysis) is a polars chain over those streams plus a small statsmodels / scipy / lifelines adapter layer, feeding three thin notebooks:

Notebook

What it produces

notebooks/01_paired_main_effects.ipynb

Within-pair contrasts for the 2×2 factorial. MixedLM + GEE so the paired design’s df is not inflated.

notebooks/02_emergence_survival.ipynb

Kaplan–Meier + CoxPH on the censored Emergence outcome. Lifecycle-state Markov summary.

notebooks/03_sensitivity_and_confounders.ipynb

Per-metric Manski bounds, paired mediation, and negative controls.

Run one arm#

uv sync

uv run train --config-path configs/mas_config.yaml --intervention baseline

Swap --intervention for baseline_opt, mem0g, or mem0g_gepa.

uv run evaluate --config-path configs/mas_config.yaml --subset 1500

uv run analyze \
    --live-root evaluation/analysis/live \
    --output-root evaluation/analysis/scientific_notebook_outputs \
    --group-by intervention,protocol,dataset_name,model_name \
    --bootstrap-samples 2000

See Quickstart for the full four-arm sequence + evaluation + analysis.
